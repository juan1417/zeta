# 7. I/O: CSV y datasets remotos

## 7.1. `load_csv($ruta)` — el camino local

```zeta
$df = load_csv("tests/datos.csv")
print($df)
```

`load_csv` lee un archivo CSV, parsea el header, infiere tipos por columna, y devuelve un `DataFrame`. **Todas las columnas se almacenan como `vector<double>`**, lo que significa que valores no numéricos se convierten a `null`.

### Formato CSV esperado

```
mes,ventas,gastos
Ene,1000,500
Feb,1200,600
Mar,1500,700
```

- **Primera fila**: header con nombres de columnas separados por comas.
- **Filas siguientes**: valores separados por comas, una fila por línea.
- **Líneas vacías**: se ignoran.
- **Valores no numéricos**: `null`, `NA`, `NaN`, `n/a`, `""` → se almacenan como `null` (NaN).
- **Texto no reconocido como número**: se almacena como `null` (no se preserva el texto).

### Trim automático

Los valores se trimean de espacios, tabs, newlines y comillas. `" 1000 "` se convierte a `1000.0`. Esto es robusto contra CSVs exportados de Excel que tienen padding.

### Ejemplo de CSV con nulls

```
mes,valor,flag
Ene,100,1
Feb,,0
Mar,150,1
Abr,NA,1
May,200,
```

```zeta
$df = load_csv("datos.csv")
print($df:valor)    # <100, null, 150, null, 200>
print(count($df:valor))    # 3 (ignora nulls)
```

### Validación de simetría

Después de parsear, el intérprete valida que **todas las columnas tengan la misma longitud**. Si no, lanza un error:

```
Error: CSV con columnas de longitudes distintas en: ruta.csv
```

### Columnas faltantes por fila

Si una fila tiene menos columnas que el header, las columnas faltantes se rellenan con `null`:

```
a,b,c
1,2,3
4,5
6
```

Resultado: columna `a` = `<1, 4, 6>`, columna `b` = `<2, 5, null>`, columna `c` = `<3, null, null>`.

## 7.2. Cliente HTTP via C ABI (libcurl)

Zeta no tiene un cliente HTTP embebido en el núcleo. Si necesitas descargar archivos desde una URL, carga `libcurl` via `load_lib` y escribe tu propio cliente. Esto mantiene el núcleo sin dependencias externas y te da control total sobre timeouts, headers, autenticación, etc.

Ejemplo mínimo de `http_get` via libcurl (ver [C ABI](./10-c-abi-loadlib.md) para más detalles):

```zeta
load_lib("/usr/lib/x86_64-linux-gnu/libcurl.so", {
    "curl_global_init": "fn($n) -> $n",
    "curl_easy_init":   "fn() -> $n",
    "curl_easy_setopt":  "fn($h, $opt, $val) -> $n",
    "curl_easy_perform": "fn($h) -> $n",
    "curl_easy_cleanup": "fn($h) -> $n"
})

# Constantes de libcurl
$CURLOPT_URL      = 10002
$CURLOPT_FOLLOWLOCATION = 52

fn http_get($url) {
    curl_global_init(0)
    $h = curl_easy_init()
    curl_easy_setopt($h, $CURLOPT_URL, $url)
    # CURLOPT_URL espera un string, pero ABI lo pasa como double;
    # necesitas un wrapper real en C si quieres pasar strings.
    $rc = curl_easy_perform($h)
    curl_easy_cleanup($h)
    return $rc
}

print("HTTP status:", http_get("https://example.com/data.csv"))
```

> **Limitación**: el ABI actual pasa doubles por valor, no strings. Para un cliente HTTP completo necesitas escribir un wrapper en C (con `ZETA_API`) que internamente use `curl_easy_setopt` con `CURLOPT_URL` y capture la respuesta, devolviendo un `double` con el status code. Ver [C ABI](./10-c-abi-loadlib.md) para el patrón completo.

## 7.3. Ejemplo completo de carga

```zeta
# Carga local
$df1 = load_csv("datos/ventas_2024.csv")
print("Filas:", len($df1))
print("Columnas:", keys($df1))
print("Suma de ventas:", sum($df1:ventas))

# Para carga remota, usa tu propio cliente HTTP via libcurl (ver 7.2)

# Verificar que no hay nulls problemáticos
if (count($df1:valor) < len($df1)) {
    print("Advertencia: hay nulls en la columna 'valor'")
}
```

## 7.4. `ZETA_PATH` para búsqueda de librerías

`ZETA_PATH` es una variable de entorno que extiende las rutas de búsqueda para módulos `.zl`. **No afecta a `load_csv`** (que toma rutas absolutas o relativas al CWD).

```bash
# En tu .bashrc
export ZETA_PATH="$HOME/.local/lib/zeta:/opt/zeta/lib"
```

## 7.5. Limitaciones actuales

- **Sin soporte para TSV/JSON/Parquet** — solo CSV.
- **Sin inferencia de tipos por columna** — todo se trata como `double` (texto → null).
- **Sin manejo de comillas escapadas** (`"a,b","c"` no se parsea correctamente).
- **Sin BOM handling** — archivos con BOM al inicio pueden fallar.
- **Sin compresión** — no se lee `.csv.gz` directamente.

Estas limitaciones son conocidas y se abordarán en sprints futuros. Para casos avanzados, usa una etapa de preprocesamiento en Python o shell.

## 7.6. Buenas prácticas

### Verificar tamaño antes de cargar

```zeta
import "fs" as fs   # NOTA: 'import' no existe en Zeta, esto es pseudocódigo
# En Zeta, tendrías que verificar desde shell antes de ejecutar
```

En la práctica, verifica el tamaño del CSV con `wc -l` antes de cargarlo.

### Cachear datasets grandes

Si tu CSV es estable, guárdalo localmente y `load_csv` desde la copia:

```bash
# Descargar una vez
curl -s -L -o datos_cached.csv https://example.com/datos.csv

# Luego en el script
./zeta -c '$df = load_csv("datos_cached.csv")'
```

### Validar después de cargar

```zeta
$datos = load_csv("datos.csv")

# Verificar que existen las columnas esperadas
if (!is_error($datos:ventas)) {
    print("Columna 'ventas' OK")
} else {
    print("ERROR: no se encontró 'ventas'")
    return
}

# Verificar no-vacío
if (len($datos) == 0) {
    print("Dataset vacío")
    return
}
```

## 7.7. Rendimiento

- **CSV de 10 MB / 100k filas**: ~200ms en hardware moderno.
- **CSV de 100 MB / 1M filas**: ~2-3s (parsing en C++).
- **CSV > 1 GB**: no recomendado, considera pre-procesar a un formato binario o usar DuckDB.

El parser es **single-threaded** y hace una pasada sobre el archivo. No hay índices, no hay cache de columnas, no hay tipos mixtos. Si necesitas más, usa otra herramienta.
